# Coinbase execution ledger and volume-at-price

## Realtime collection

Run `npm run stream:trades` from the repository root alongside `npm run dev` (or the production web server). The collector is an independent long-running Node process, not a scheduled job or a Next route handler. Stop with Ctrl+C. No account credentials, order submission, service installation or extra dependencies are involved. `--ledger ABSOLUTE_PATH` selects the ledger; the dashboard must use the same path. The CLI reads process environment, not `terminal/.env.local`.

The collector subscribes to public Coinbase BTC-USD `matches`, `heartbeat` and `level2_batch` on the same WebSocket connection. It ignores the initial `last_match` snapshot, validates executions, batches durable writes every second, and retains immutable ID deduplication and conservative observation timestamps. A renewable SQLite lease prevents two live collectors sharing one ledger. After a crash, that lease expires in 15 seconds. Existing bounded REST collection can still run against the WAL ledger.

Startup/reconnect recovery pages backwards from the REST head to the last continuous durable trade ID. Live prints keep buffering/committing during recovery. Heartbeat last-trade IDs and arithmetic execution-ID holes trigger repair; WebSocket sequence numbers are not treated as a consecutive trade-ID stream. A 10-second heartbeat watchdog closes a stalled connection; reconnect uses exponential backoff with jitter capped around 30 seconds. REST retries transient failures/429s with bounded Retry-After waits. Recovery is bounded to 50 pages by default: `npm run stream:trades -- --recovery-pages 200` increases this budget (maximum 1000). Exhaustion, missing IDs and failed requests remain GAP; new prints do not silently clear the unresolved anchor, which survives restarts. A sufficiently long outage may require a larger budget or manual REST backfill. Historical gaps older than the initial continuity anchor remain represented by profile coverage, not certified by a LIVE status.

Market > Price now has a separate live execution workspace: last execution/time, heartbeat and feed state, forming one-minute OHLC/volume, latest 20 captured executions, and a rolling 15-minute actual-trade profile. The browser receives coalesced one-second snapshots through `GET /api/market/trades/live` (SSE); the profile refreshes every five seconds while heartbeats accompany LIVE, GAP or RECOVERING states; coverage remains explicit during recovery. Reads are read-only SQLite snapshots, hash-validated and bounded. Slow SSE consumers do not accumulate an unbounded tick queue; cancellation clears timers. Dead collector metadata becomes STALE after ten seconds. SSE transport errors display RECONNECTING while EventSource retries.

The header, main chart and execution workspace share one browser SSE subscription. The header shows the latest captured execution with its UTC timestamp and actual collector/transport freshness; it stays live during replay and is explicitly separate from replay prices. Its 24-hour change is unavailable unless a captured, validated execution exists within one minute before the 24-hour comparison boundary; the old server percentage is never paired with a new live price.

For eligible Coinbase chart windows, the stream accepts interval and aligned from parameters and returns native-interval ledger bars (maximum two days / 200,000 executions). Complete coverage requires adjacent trade-ID evidence preceding the interval, no internal holes, and a following execution after closed intervals. Forming intervals are labelled, including partial captured coverage. Missing intervals are not synthesized as zero-volume candles. Chart payload versions include forming content; indicators, pivot references and historical studies use complete closed bars at the same cutoff. Updates replace tail bars by timestamp instead of accumulating volume twice. Zoom and pan state remain intact as prices change. If a window exceeds read limits, reload the timeframe window; feed health and header quotes remain available.

Start replay freezes the currently available completed market dataset and cutoff; incoming prints cannot enter replay charts, overlays, indicators or studies. Chart aggregation and live profile updates disconnect during replay/archive inspection/non-Coinbase or mock charts, while the independent header quote remains live. Exiting replay requests the current ledger tail again. Strict historical profiles still reject executions first observed after the replay cutoff. The live order-book/DOM panel is isolated from replay as described below. A historical liquidity heatmap is not implemented.

The public [Coinbase Exchange product trades endpoint](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-trades) supplies BTC-USD execution ID, time, price, size and maker side. Collection uses the response's `CB-AFTER` header to request older pages, following [Coinbase cursor pagination](https://docs.cdp.coinbase.com/exchange/rest-api/pagination). No trading credentials or account orders are used.

## Collect locally

From the repository root:

```powershell
npm run ingest:trades -- --pages 5
npm run ingest:trades -- --resume --pages 20
npm run ingest:trades -- --pages 100 --until 2026-10-13T00:00:00Z
```

The first command captures recent prints. Repeating it deduplicates overlapping trade IDs and catches newer prints. `--resume` continues older pagination from the persisted oldest checkpoint. A head catch-up after a long interruption may need a larger page budget and an `--until` target to bridge the interruption; resuming the oldest checkpoint alone does not fill a middle gap. Collection is finite, rate-paced and bounded to 1–1000 pages of up to 1000 prints each. A target date not reached before the page budget remains explicitly unreached. No claim is made that the endpoint can backfill to 2015. No background service or scheduler is installed.

Default storage is `artifacts/market/coinbase_trades.sqlite`, separate from hourly/minute candle databases and ignored by Git. Use `--ledger ABSOLUTE_PATH` or `IRIS_TRADE_LEDGER_PATH` to select another ledger. Configure the same absolute `IRIS_TRADE_LEDGER_PATH` in `terminal/.env.local` for the dashboard. The CLI reads its process environment, not Next's env file automatically. Node >=22.13 is already required by this repository; no dependency is added.

## Live order book and DOM

The same collector subscribes to Coinbase's public [`level2_batch` feed](https://docs.cdp.coinbase.com/exchange/websocket-feed/channels), which batches updates every 50 ms. It maintains the full received BTC-USD L2 book in memory, using exact eight-decimal integer price/size units. The snapshot establishes initial depth; `l2update` sizes replace the quantity at a price, and zero removes the level. Updates are processed in stream order. This channel does not supply an execution-style sequence counter; trade-ID recovery cannot repair depth. Every disconnect discards the old book and requires a fresh WebSocket snapshot. Malformed, crossed, oversized or decreasing-event-time updates invalidate depth and reconnect; arbitrary updates never seed an empty book.

The in-memory bound is 100,000 price levels per side. `iris_trade_meta.live_order_book` stores only the current nearest 500 levels per side, full level counts, session identity, snapshot/observation/event times, connection state and SHA-256 for the bounded published representation. It replaces this current view once per second alongside execution collection. This is not an archive of depth changes or historical books. Fresh heartbeats plus a valid snapshot are required for LIVE; disconnected/invalid/stale/stopped publications expose no levels. Readers verify the metadata/hash, ordering and spread. Missing or invalid depth does not disable valid trade quotes. `GET /api/market/trades/live?book=true` includes depth on the existing SSE connection; header-only subscriptions omit it.

Market > Price > ORDER BOOK / DOM shows a descending-price ladder with asks above the spread and bids below. Controls select USD price grouping (0.01, 1, 5, 10, 25, 50, 100), 10/20/40 rows per side and spread following. Bids group down and asks group up. Displayed quantities and cumulative BTC use exact integer sums; histogram widths are visual approximations. Cumulative depth and bid share describe displayed rows only, not the entire venue book. Grouping uses the published nearest 500 raw levels per side and never fills synthetic price levels. Recent matched BTC comes from the latest 20 captured executions and their maker side, not an interval footprint or inferred pressure signal. Depth is resting liquidity and does not enter executed-volume profiles.

Replay, archive inspection, mocked data and other chart venues disable the DOM immediately and remove book requests from the workspace subscription. The header retains its independent live quote. Exiting replay requests the current book again; live depth is never assigned a historical replay timestamp. A stale SSE transport hides the ladder even if a previous depth payload was LIVE.

Live context consumers use a hydration-aware `useSyncExternalStore` server snapshot. Each SSR/Suspense consumer initially sees the same null/CONNECTING placeholder on the server and during its hydration, even if its parent already received live SSE data. It adopts live context after hydration. This resolves the reported late-header STALE/LIVE hydration mismatch without suppressing mismatches or delaying collection.

## Storage and integrity

Live validation found Coinbase REST/WS serialization of the same execution timestamp differing by one microsecond. Collectors accept that exact discrepancy only when trade ID, price, size and maker side match. The canonical first timestamp, original content hash and first-observation watermark remain unchanged; `trade_time_aliases` records the alternate microsecond timestamp, hash and observation time, while page audits retain original payload hashes. Larger discrepancies and execution-value changes still reject the transaction. Exact historical boundaries use the canonical first timestamp; this one-microsecond source discrepancy is not silently rounded away.

Execution times preserve exchange microseconds. USD prices and BTC sizes use fixed eight-decimal integer strings. Profiles accumulate BTC units with BigInt, and notional uses the exact product of price/size units. Display meters use numeric approximations; reported totals and per-bin quantities retain exact decimal strings. Decimal scientific notation or precision beyond eight places is rejected rather than silently rounded.

Trade IDs are immutable primary keys for this BTC-USD ledger. Repeat prints retain their first observation time. Conflicting content rejects the entire page transaction, including new trades in that page. SHA-256 verifies canonical execution fields on profile reads. Page audits retain fetch time, request/response cursor, row count, ID bounds and response content hash. Successful rows, page audit and older checkpoint commit together. A newest-page refresh cannot replace a deeper historical checkpoint. Observation time is a conservative upper bound of the local receiving millisecond, not an externally signed historical availability certificate.

Malformed/unordered pages, non-advancing cursors, incompatible schema/product, invalid values or mismatched content hashes fail closed. Requests are paced at <=4/s between successful pages and retry bounded transient failures/429 responses. Existing candle archives are not migrated or overwritten.

## Profile UI and cutoff

Market > Price > Advanced Market Studies > Executed-trade volume profile supports Snapshot window, Last 15 minutes, Last hour and Last 24 hours. **Load trade profile** reads the persisted ledger only. A changed window, market cutoff, strict flag or venue hides a previous profile until it is reloaded. A mocked or non-Coinbase chart cannot silently borrow Coinbase executions. The profile follows the snapshot/replay cutoff, not viewport-only chart zoom. Actual completed executions can extend beyond the last completed OHLCV candle while staying before the same snapshot cutoff.

`GET /api/market/trades/profile` requires UTC `start`, `end` (exclusive), `cutoff`, optional `bins` (2–50) and `strict`. It accepts microsecond boundaries, checks end<=cutoff<=now and limits a query to 366 days / 200,000 trades. Choose a narrower window if the query is too large. Reads use a read-only SQLite snapshot. Response quantities are actual executions only; there is no candle fallback.

Reconstruction reads the selected execution-time range at the current observation watermark. Strict mode also requires first-observed time <= historical cutoff. Historical data not yet gathered stays EMPTY, including a 2015 replay when only recent executions exist.

Coverage is EMPTY, PARTIAL or CONTIGUOUS_ID_EVIDENCE. ID holes are arithmetic evidence, not a guaranteed count of missing executions. Continuity evidence additionally requires known adjacent trade IDs outside both time boundaries. Even contiguous IDs are not an independent completeness certificate. Requested and globally captured bounds are shown separately; a partial ledger never represents all volume in a wider requested period. Source labels remain development-only; quality and dates remain visible in production.
