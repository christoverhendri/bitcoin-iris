# IRIS lightweight news parser

Implementation: `news_pipeline/parser.py`, version `iris-news-rules/1.0.0`.
English, standard-library rules, no new dependency, GPU, embedding service or model
weights. This is a conservative structural/event-cue parser, not a trained semantic
model. The sentiment classifier remains unchanged.

## Run

From the IRIS repository root:

```powershell
.venv/Scripts/python.exe -m news_pipeline parse --text "SEC has not approved Bitcoin ETF."
.venv/Scripts/python.exe -m news_pipeline parse --input "bitcoin iris/dataset/kategori/textual_news/watcher_guru_articles.jsonl" --output artifacts/news/parsed_history_v1.jsonl
```

The JSONL command preserves every original field, including historical parse and
assessment, and adds `semantic_parse`. Existing output paths are refused. It streams
one record at a time; malformed JSON or invalid raw_text fails explicitly, and a
partial output can remain. Choose a new output filename for reruns. Text mode can
write JSON with `--output`. Parsing requires no trained sentiment artifact.

`predict` and new `poll` results automatically include the same `semantic_parse`.

## Output contract

- `segments`: boundaries with negation, modality and attribution cue spans.
- `entities`: known aliases (BTC/XBT/Bitcoin, ETH/Ethereum, selected organizations)
  and cashtags. Dictionary matches are candidates, not general entity recognition.
- `quantities`: explicit currency symbols, amounts/scales, percentages, basis points
  and asset units. Decimal values are strings to preserve precision. `$` remains
  a symbol, not an assumed USD currency. Quantity-to-event roles remain unresolved.
- `time_expressions`: literal time expressions; relative dates are not invented.
- `events`: supported lexical triggers with segment evidence and local entity
  mentions. `polarity` describes affirmation/negation, not sentiment.
- `modality`: asserted, expected, planned, possible, conditional, rumored, unresolved.
- `ignored_spans`: masked URLs, mentions and alert prefix. Raw text is preserved.
- `unresolved`, `needs_review`: unsupported content or complex scope.

Every span uses half-open Python Unicode code-point offsets into `raw_text`:
`raw_text[start:end] == text`. JavaScript consumers must convert code-point indices
before slicing UTF-16 strings containing emoji. Do not use cleaned_text for spans.
Telegram `<br>` becomes a newline and inline formatting preserves joined words.

Examples:

| Input | Parsed event | Polarity | Modality |
|---|---|---|---|
| SEC approves Bitcoin ETF. | approval | affirmed | asserted |
| SEC has not approved Bitcoin ETF. | approval | negated | asserted |
| Analysts expect SEC to approve Bitcoin ETF. | approval | affirmed | expected |
| Exchange denies it was hacked. | security_incident | negated | asserted |
| Exchange did not deny it was hacked. | security_incident | unresolved | unresolved |

`asserted` means the linguistic statement is asserted; it does not certify an
event occurred. `verified_occurrence` is always false. Actor, target and speaker
remain null: the parser exposes local mentions/cues without claiming role resolution.

Simple negation applies only over a restricted auxiliary-word pattern. Multiple
triggers, conjunctions, trailing modality/negation and nested negation are marked
unresolved. Attribution/modality from an earlier segment causes conservative
review of later un-attributed events; full quotation/coreference scope is not
implemented. Unknown entities and unsupported triggers are not fabricated.

No source credibility, market impact, sentiment score or learned confidence is
generated by these rules. Event matches can be false positives (e.g. polysemous
words); review flags and rule coverage do not measure accuracy. Keep the parser
output separate from human gold labels and the historical heuristic assessment.

## Persistence

New content hashes use raw_text, so edits to mentions or formatting remain distinct
versions and evidence offsets refer to the stored version. A matching legacy row
using the cleaned-text hash is upgraded only when its raw text exactly matches.
An existing row gets a missing/outdated semantic_parse refreshed on the next poll,
preserving its original observation time and sentiment model output. The existing
`inserted` counter counts new rows, not parser refreshes. Unseen old rows can be
reprocessed through JSONL export/parse; polling does not revisit the full database.

## Validation on 2026-09-05

- 14 automated tests passed, including scope contrast, nested denial, quantities,
  Unicode offsets, HTML line breaks, raw-only edits and legacy row upgrades.
- All 9,471 historical records parsed; 63,404 emitted spans checked against source
  text, with zero invalid offsets.
- 2,128 records contained a supported event trigger; 8,753 were flagged for review.
  This reflects deliberately limited rule coverage, not semantic accuracy.
- Warm parser-only pass over the loaded corpus: 0.983 seconds on this machine.
  Excludes I/O and model inference; it is one local timing, not a latency guarantee.
- Live smoke run: 17 posts fetched/classified/stored in a separate SQLite database.

Next parser work should be driven by a labelled error sample: expand event rules,
improve clause/quotation scope, then evaluate role extraction. Avoid reducing review
counts by silently assigning a default interpretation.
